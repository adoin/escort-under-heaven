# 武侠像素 RPG｜系统映射与 MVP 设计

用 Godot 4 做一款像素风武侠格子回合 RPG。玩家作为初入江湖的游侠，在县城接榜，沿官道或山路深入危险据点，再带着赏银、伤势和线索回客栈。首版验证玩家是否会根据局势主动撤退，以及能否用上一趟的经验改变下一趟的准备。

## 十项系统映射

原型规则详见[《Stoneshard》玩法拆解](stoneshard-deconstruction.md)。下表中的武学、道具、地图和规则均为本项目设计提案。

| 系统 | 原系统 | 武侠版 | 保留什么 | 改掉什么 | 为什么这样改 |
| --- | --- | --- | --- | --- | --- |
| 01 核心循环 | 佣兵接契约，搜掠后回城整备 | 游侠在县城接榜，查寨取证，回客栈交榜、疗伤和习武 | 出门前投入、途中判断、回城兑现 | 收入来自赏银和行货，引出镖货失踪与门派调查 | 榜单提供清晰的短期目标，武学和人脉解释长期成长 |
| 02 世界 | 阿尔多各聚落、野外地块、地牢 | 原创县城、官道林径、山寨、废观和密窟 | 安全据点、风险路线、可选支路和高风险终点 | 大陆规模收为一县，地牢生态换成寨哨、藏货间和险地 | 小地图也能让地标、差异路线和撤退距离产生决策 |
| 03 战斗 | 格子回合、射程、遮挡、换武器与施法 | 刀剑进退、拳掌震退、暗器牵制，轻功跃步，内功消耗内力 | 一拍只能做一件事，争位置和安全用药窗口 | 魔法改为内外功，P0 采用四向网格、门墙遮挡、固定敌方顺序 | 四向和固定顺序便于触屏预览，武学效果从动作和距离中读出来 |
| 04 成长 | 无职业，属性、能力树、装备联动 | 无门派锁的游侠，先做基础调息、刀剑两种外功和基础轻功，后续扩展拳掌、暗器、医术和进阶内功 | 投资机会成本、武器门槛和跨树搭配 | 起始身份改为习武背景，向师傅请教或打听秘籍开放节点 | 先验证内功、外功、轻功三分法，再扩充树和装备量 |
| 05 伤病 | 部位伤、出血、疼痛、毒素及精神生存 | 金创药止血，接骨处理重伤，运功缓解内伤，心境影响内功 | 紧急处置与长期康复分层，伤势持续到返程 | P0 只做流血与腿伤。后续扩展中毒、饥渴、心境及走火入魔。放血替换成武侠虚构的解毒药和内功交互 | 先教会识别持续掉血与跑不动，再逐步加长线管理 |
| 06 经济 | 契约、物价、跑商、随从与商队营地 | 悬赏、商号、镖队、趟子手、医师和临时落脚点 | 毛利与净利、货物占位、远征后勤投资 | P0 只有本地买卖、修理和赏银。后续向镖队雇用和区域差价扩展 | 先让打完一趟的钱有用途，镖队扩张再改变长期路线 |
| 07 探索任务 | 晶石谜团、契约、地点发现和随机遭遇 | 失镖奇案、榜单委托、行脚人口述、埋藏物和可变巡哨 | 短期赏银、中期探索、长期谜题可以并行 | 换成原创案件、人物与地点。P0 用物证触发一段线索和一个可选藏宝点 | 玩家可以选择带证据先撤或多走一段找财物 |
| 08 存档与死亡 | 床铺及营地检查点、退出续玩和可选永久死亡 | 客栈或驿站投宿，暂停恢复，上一次投宿为标准死亡回退点 | 安全点的价值和出门后的损失预期 | 手机离开时自动记录会话，默认用较短路线控制回档跨度，铁人后做 | 午休或切后台也能玩，战斗中仍要处理伤势并承担死亡后果 |
| 09 硬核难度 | 准备、站位、敌情误判和连锁负伤 | 试招、探路、接近威胁格确认、带伤撤离 | 行动可追溯、补给有限、撤退是有效策略 | 首遇流血在安全演练中解释，低血与致命持续伤害高亮 | 保住战术难度并让死亡原因能复盘 |
| 10 表现 | 像素中世纪，昏暗地牢与交战反馈 | 原创市井、竹影、油灯山寨，梆子、脚步与不同兵刃音色 | 场景切换传递远离安全区，攻击和受伤反馈清楚 | 采用自制地形、人物轮廓和调色。危害用图形与声音双提示 | 建立可辨认的江湖气质，小屏和静音下保有战斗可读性 |

## MVP 优先级

**本次调整。** 补充镖局开局、门派故事入口和三条结局线的 P0/P1/P2 分期。同步调整「04 成长」、P0 可玩性验收及建议制作顺序，加入内功、外功、轻功的最小配合验证。完整方案见[主线、结局与武功](mainline-endings-and-martial-arts.md)。

| 优先级 | 交付内容 | 理由 |
| --- | --- | --- |
| P0 | 一处县城安全点、一张林道含岔路、一处单层寨地和明确返程 | 验证路线、搜寻与撤回的最小闭环 |
| P0 | 格子移动、等待、普攻、武技、快捷用药、战斗中切换武器组，至少两种敌人，墙体与门洞遮挡 | 让行动预算、距离、视线和先后顺序有实战用途 |
| P0 | 一段镖局收留开场、一张取证榜、一个可选藏宝点和一个可选的门派故事入口，能交榜、失败和撤离 | 验证县城接榜、林道入寨取证、回客栈交榜整备的循环，以及结算后如何引出下一趟 |
| P0 | 生命、流血、腿伤、金创药和客栈疗养，固定格数背包，赏银与最小买卖修理 | 建立伤病成本与净收益，验证活着回城的价值 |
| P0 | 内功一门基础调息，外功为刀剑各一招并共用基础格挡，轻功一招共用跃步，保留升级选点和有限装备 | 验证调息与注劲、出招与格挡、位移与伤病约束能否形成取舍 |
| P0 | 客栈检查点、会话续玩、标准死亡回退，触控预览、首次止血提示、基础像素与音效反馈 | 让失败可理解、动作可操作，移动端的短会话能完整中断与恢复 |
| P1 | 第二个聚落及物价差、简单镖队营地与一种随从服务、更多榜单、路线变化与两三种遭遇 | 闭环确认后再验证跑商和长线后勤能否改变路线 |
| P1 | 合并式体力补给、毒与解毒、拳掌和暗器、战斗光照与听觉的有限规则 | 增加武学与风险组合，逐项验证信息负担和装备反制 |
| P1 | 扩展少量属性内功和相克，试验外功体力消耗，验证轻功闪避、低障跳跃与潜行 | 验证三分法扩展后在战斗与探索中是否容易理解 |
| P1 | 三条结局线各做一个早期节点。一人之下试做官面查案，富可敌国试做商号信用与货单，武林至尊试做门派调停与支持 | 验证声望、选择的跨线影响以及错过节点后的替代入口 |
| P2 | 完整镖队升级、多区域开放地图、更多学派与生成地牢、复杂心境和疾病以及可选铁人 | 与地图规模、数值平衡或大量内容绑定，等循环稳定后评估成本 |
| P2 | 扩展徒手与兵器大类、进阶内功和轻功。完成锦衣卫或东厂任命、明朝首富核验、武林盟主推举，以及职务互斥和结局后续玩 | 完成三线终局，验证同档并行、先后达成和失败恢复 |

## 硬核点和移动端取舍

以下节奏和数值是本项目首轮试玩目标。通关一趟暂以约 15–25 分钟为假设，按测试中的回档跨度和重复操作量调整。

| 决策压力 | 首版规则 | 手机与轻度方案 |
| --- | --- | --- |
| 行动有代价 | 走一步、等待、攻击、用药、切组各一拍。查看、取消和无效输入为零拍 | 点格先预览，多步移动遇敌或危险状态自动停下。危险格和不可逆提交需确认，可在设置中调整 |
| 敌人有反应窗口 | 玩家有效动作结算后，可行动的敌人按固定顺序依次行动，最后处理状态与环境。出血按轮末处理 | 显示已知敌人下一次威胁，战报指出本轮伤害来源。动画可加速，规则顺序不随帧率改变 |
| 伤病影响撤离 | 出血每轮伤生命。腿伤禁用轻功位移，保留普通步行。金创药停流血，投宿治疗腿伤 | 状态按钮显示下一跳后果和推荐治疗，常用药放快捷栏。轻度选项增加初始药和一次低价疗养 |
| 后勤有取舍 | 先用一个固定格数背包，任务物独立保管。野外携带药、拾取战利品互相争格 | 点选拾取、自动堆叠或排序，安全区自动补货可预览价格。饥渴先由一项补给承接，放到 P1 |
| 失败要付代价 | 标准模式死亡回客栈检查点，丢失该点之后的收获和进度。会话快照在已结算回合恢复 | 轻度可在寨门外设置单次检查点。挂起续玩保留当前状态，死亡后同一趟的续玩记录失效 |
| 路线承担风险 | 林路短而有伏击压力，官道长且能预判巡哨。两条路都支持原路撤退 | 界面显示到安全点的方向、路线距离和已见危险，避免触屏反复拖图找路 |

### P0 可玩性验收

- 从接榜到第二次出门可完整走通。至少一次选择在发现藏宝点后带证撤回，且能在交榜后买药或修理兵器。
- 同一间哨房可以用剑法和轻功卡距离，或用刀法抢门洞并短程压制。敌人会对等待和用药作出相同的行动响应。
- 首次流血提示后，玩家能判断哪一个道具先用。腿伤时仍有步行撤离路线。意外死亡能定位到关键行动和持续伤害。
- 手机切后台再恢复后，位置、回合、任务物、敌人状态与药品数量一致。死亡回档后，已失效的会话无法重新打开。
- 从镖局收留开场走到交榜，物证可触发一个门派故事入口。搁置线索后仍能继续接委托。
- 调息、刀剑招式和跃步各自消耗一拍，敌方正常响应。用刀剑注劲或跃步后可调息回内，腿伤时仍可步行撤离。

## Godot 模块建议

使用 Godot 4 的场景组织表现，`Resource` 保存策划配置。战斗格子、回合、任务和存档各有明确状态来源，界面从已提交结果更新。技术选型见 [Godot 节点与场景][scenes]、[TileMapLayer][tile]、[Resource][resource] 和 [存档指南][saving]。

| 模块 | 职责与状态归属 | 交互和选型 |
| --- | --- | --- |
| 世界与地图 | 区域入口、可走格、遮挡、门状态、探索记录及实例变更 | 场景与 `TileMapLayer` 负责呈现。规则查询通行、射线和占位，寻路可用 `AStarGrid2D`。[AStarGrid2D][astar] |
| 回合与战斗 | 校验指令、计拍、单位顺序、命中与伤害、状态结算、敌人决策 | 向地图查询可达和视线，向角色与物品查询行动条件。结算后发出回合结束、击倒和战报事件 |
| 角色与武学 | 持有生命、部位伤、内力、已学节点和装备组，提供派生属性 | 武学和状态定义使用 `Resource`，实例数值由当前会话持有。战斗结算伤害和状态，升级应用点数 |
| 物品与经济 | 背包、装备转移、消耗、耐久、钱包与商店价格 | 物品使用经回合校验，交榜与买卖一起提交款项和库存变化。商店、战斗界面读取同一库存 |
| 任务与探索 | 榜单目标、接取、可交付、失败、奖励和解锁条件 | 监听拾取、击倒、地区进入与回合时间。按任务实例记录交付状态，重复读取或事件重发时不重复发奖 |
| 存档与会话 | 检查点、会话快照、存档版本与恢复，记录已结算回合、随机状态、地图差异、角色、库存与任务 | 存稳定内容 ID 和实例状态。把快照写到 `user://`，写入并校验后替换旧文件，失败时保留旧记录。[FileAccess][file] · [存档指南][saving] |
| 界面、像素表现与音频 | 触控输入、走格预览、血量伤势、任务日志、战报、动画和音效 | `Control` 组 UI，意图提交给回合或交互模块。规则事件驱动视听反馈，退后台时从上一个结算点恢复 |

### 一拍与一趟的交互顺序

1. 玩家触控提交意图。回合模块查询地图、角色和物品库存，确认射程与合法性。预览和无效输入保持当前回合。
2. 玩家动作结算，按稳定单位编号处理有资格行动的敌人。每个敌人根据当时的占位、视线选动作。轮末结算持续状态和环境，聚合该轮事件。
3. 任务模块消费已结算事件并更新目标。回合模块在任务状态一致后发布整轮结果，界面更新战报，保存模块写入会话快照。移动端每轮保留最新已提交状态，后台通知可触发立即写入。
4. 回城交榜时，任务模块和库存模块一并处理证物、赏银和已交付标志。投宿成功后更新检查点。死亡优先使对应会话快照失效，再按模式恢复检查点。

### 建议制作顺序

先打通一张占位小图的计拍、敌人、状态和复盘，再接客栈与单张榜单，接着跑通经济、装备和两种武学打法。在这条循环中接入镖局开场和可选门派线索，用基础调息、刀剑招式和跃步验证三分法。最后用真实手机验证触控操作、后台恢复、死亡回档及出入口表现，依据试玩再扩充地图内容。
